0.  STORAGE STRATEGY & DESIGN LAWS
═════════════════════════════════════════════════════════════════════════════

0.1  WHY POLYGLOT

  A single engine cannot serve four fundamentally different access patterns:

    (1) Transactional, relational, ACID          → PostgreSQL
        cases, users, dossiers, audit, registry
    (2) Deep multi-hop typed traversal           → Neo4j / Memgraph
        the transaction multigraph, chain-sharded
    (3) Sub-millisecond hot lookup + queueing    → Redis
        edge cache, rate-limit buckets, task broker, locks
    (4) Large immutable binaries                 → S3-compatible object store
        dossier PDFs, model artefacts, raw provider payloads

  Forcing (2) into PostgreSQL produces recursive CTEs that die at depth 6 on
  a hot wallet. Forcing (1) into Neo4j loses the ACID guarantees that legal
  artefacts require. The split is deliberate, not incidental.

0.2  THE SEVEN DESIGN LAWS (violating any is a review blocker)

  LAW 1 — MONEY IS NEVER A FLOAT.
    All values are NUMERIC(78,0) storing base units (wei, satoshi, sun,
    lamports). 78 digits covers uint256. Decimals live in the asset table.
    A FLOAT/DOUBLE column holding a value amount fails code review.

  LAW 2 — FACTS ARE IMMUTABLE, OPINIONS ARE VERSIONED.
    Ledger facts (tx, block, transfer) are INSERT-only. Classifications,
    scores, and annotations are append-only versioned rows. Nothing that has
    entered a dossier is ever UPDATEd.

  LAW 3 — EVERY ROW KNOWS WHERE IT CAME FROM.
    ingest_run_id, source provider, fetched_at, and payload digest are
    mandatory on all externally-sourced data.

  LAW 4 — AUDIT IS APPEND-ONLY AT THE DATABASE LEVEL.
    Enforced by revoking UPDATE/DELETE and by a BEFORE trigger that raises.
    Not by application discipline.

  LAW 5 — BLOCK HEIGHT IS AUTHORITATIVE FOR ORDER; TIMESTAMPS ARE ADVISORY.
    Miners/validators can lie about time. They cannot lie about height.

  LAW 6 — ADDRESSES ARE STORED CANONICAL + RAW.
    address_canonical (lowercased hex / checksummed per chain rules) for
    joining; address_raw (exactly as observed) for evidentiary fidelity.

  LAW 7 — DETERMINISM IS PERSISTED.
    Every trace stores model versions, parameter set, RNG seed, and
    snapshot id. Without these, PRD principle P4 is unenforceable.

0.3  NAMING CONVENTIONS
  - snake_case, plural table names, singular column names.
  - Primary keys: `id` UUID v7 (time-ordered) unless a natural key exists.
  - Foreign keys: `<referenced_table_singular>_id`.
  - Timestamps: TIMESTAMPTZ, always UTC, suffix `_at`.
  - Booleans: prefix `is_` / `has_`.
  - Enums: PostgreSQL native ENUM for closed sets that change rarely; a
    lookup table where operators must add values without a migration.
  - Indexes: `ix_<table>_<cols>`; unique: `ux_`; partial: append `_partial`.

1.  SYSTEM-OF-RECORD MAP
═════════════════════════════════════════════════════════════════════════════

  ┌────────────────────────────┬───────────────┬────────────────────────────┐
  │ Data                       │ System of     │ Replicated to              │
  │                            │ record        │                            │
  ├────────────────────────────┼───────────────┼────────────────────────────┤
  │ Users, roles, cases        │ PostgreSQL    │ —                          │
  │ Canonical transactions     │ PostgreSQL    │ Neo4j (as edges)           │
  │ Address registry           │ PostgreSQL    │ Neo4j (as nodes)           │
  │ Graph topology & traversal │ Neo4j         │ — (derived, rebuildable)   │
  │ Classifications            │ PostgreSQL    │ Neo4j (node property cache)│
  │ Merkle proofs              │ PostgreSQL    │ Object store (bundle)      │
  │ Dossier PDFs               │ Object store  │ PostgreSQL (metadata+hash) │
  │ Model artefacts            │ Object store  │ PostgreSQL (registry)      │
  │ Audit log                  │ PostgreSQL    │ WORM archive (Phase 5)     │
  │ Hot edge cache             │ Redis         │ — (rebuildable)            │
  │ Task queue                 │ Redis         │ — (transient)              │
  └────────────────────────────┴───────────────┴────────────────────────────┘

  RULE: Neo4j is a DERIVED store. It must be fully rebuildable from
  PostgreSQL. If Neo4j is lost, no evidence is lost. This is a deliberate
  resilience property — the graph engine is an accelerator, not a vault.

4.  POSTGRESQL — IDENTITY, RBAC & JURISDICTION
═════════════════════════════════════════════════════════════════════════════

-- ───────────────────────────────────────────────────────────────────────────
-- organizations : the LEA unit hierarchy. Jurisdictional scoping anchors here.
-- ───────────────────────────────────────────────────────────────────────────
CREATE TABLE organizations (
    id                  UUID PRIMARY KEY,
    parent_id           UUID REFERENCES organizations(id),
    org_code            TEXT        NOT NULL UNIQUE,   -- e.g. 'TN-VLR-CCPS'
    display_name        TEXT        NOT NULL,
    org_type            TEXT        NOT NULL,          -- DISTRICT_CELL |
                                                       -- STATE_HQ | I4C | FIU
    state_code          TEXT,                          -- ISO 3166-2:IN
    is_active           BOOLEAN     NOT NULL DEFAULT TRUE,
    created_at          TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at          TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT ck_org_no_self_parent CHECK (id <> parent_id)
);
CREATE INDEX ix_organizations_parent ON organizations(parent_id);

COMMENT ON TABLE organizations IS
  'Hierarchy drives default case visibility. A trace is visible to the owning
   org and its ancestors, never to siblings, unless an explicit grant exists.';

-- ───────────────────────────────────────────────────────────────────────────
-- users
-- ───────────────────────────────────────────────────────────────────────────
CREATE TABLE users (
    id                  UUID PRIMARY KEY,
    organization_id     UUID        NOT NULL REFERENCES organizations(id),
    external_subject_id TEXT        UNIQUE,   -- SSO 'sub' claim. NULL = local
    username            TEXT        NOT NULL UNIQUE,
    full_name           TEXT        NOT NULL,
    rank_designation    TEXT        NOT NULL, -- printed on legal instruments
    service_id_number   TEXT,                 -- badge / PIS number
    official_email      TEXT        NOT NULL,
    password_hash       TEXT,                 -- NULL when SSO-only
    mfa_enrolled        BOOLEAN     NOT NULL DEFAULT FALSE,
    signing_key_ref     TEXT,                 -- HSM key handle, NOT the key
    is_active           BOOLEAN     NOT NULL DEFAULT TRUE,
    deactivated_at      TIMESTAMPTZ,
    last_login_at       TIMESTAMPTZ,
    failed_login_count  INT         NOT NULL DEFAULT 0,
    created_at          TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at          TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT ck_users_auth_present
        CHECK (external_subject_id IS NOT NULL OR password_hash IS NOT NULL)
);
CREATE INDEX ix_users_org ON users(organization_id) WHERE is_active;

COMMENT ON COLUMN users.signing_key_ref IS
  'Opaque HSM/KMS handle. Private key material MUST NOT exist in this DB.';

-- ───────────────────────────────────────────────────────────────────────────
-- roles / permissions / user_roles
-- ───────────────────────────────────────────────────────────────────────────
CREATE TABLE roles (
    id                  SMALLINT PRIMARY KEY,
    role_code           TEXT NOT NULL UNIQUE,  -- IO, ANALYST, SUPERVISOR,
                                               -- LEGAL, ADMIN, AUDITOR,
                                               -- MODEL_CURATOR
    display_name        TEXT NOT NULL,
    description         TEXT NOT NULL,
    is_read_only        BOOLEAN NOT NULL DEFAULT FALSE
);

CREATE TABLE permissions (
    id                  SMALLINT PRIMARY KEY,
    permission_code     TEXT NOT NULL UNIQUE,  -- 'case.create',
                                               -- 'trace.launch',
                                               -- 'dossier.sign', ...
    description         TEXT NOT NULL,
    is_privileged       BOOLEAN NOT NULL DEFAULT FALSE  -- forces re-auth
);

CREATE TABLE role_permissions (
    role_id             SMALLINT NOT NULL REFERENCES roles(id),
    permission_id       SMALLINT NOT NULL REFERENCES permissions(id),
    PRIMARY KEY (role_id, permission_id)
);

CREATE TABLE user_roles (
    user_id             UUID     NOT NULL REFERENCES users(id),
    role_id             SMALLINT NOT NULL REFERENCES roles(id),
    granted_by          UUID     NOT NULL REFERENCES users(id),
    granted_at          TIMESTAMPTZ NOT NULL DEFAULT now(),
    expires_at          TIMESTAMPTZ,
    PRIMARY KEY (user_id, role_id)
);
CREATE INDEX ix_user_roles_expiry ON user_roles(expires_at)
    WHERE expires_at IS NOT NULL;

-- ───────────────────────────────────────────────────────────────────────────
-- case_access_grants : explicit, time-bounded cross-jurisdiction access
-- ───────────────────────────────────────────────────────────────────────────
CREATE TABLE case_access_grants (
    id                  UUID PRIMARY KEY,
    case_id             UUID NOT NULL,              -- FK added after cases
    grantee_user_id     UUID NOT NULL REFERENCES users(id),
    granted_by          UUID NOT NULL REFERENCES users(id),
    justification       TEXT NOT NULL,
    access_level        TEXT NOT NULL,              -- READ | CONTRIBUTE
    granted_at          TIMESTAMPTZ NOT NULL DEFAULT now(),
    expires_at          TIMESTAMPTZ NOT NULL,
    revoked_at          TIMESTAMPTZ,
    CONSTRAINT ck_grant_window CHECK (expires_at > granted_at),
    CONSTRAINT ck_grant_justified CHECK (length(justification) >= 20)
);
CREATE INDEX ix_grants_active ON case_access_grants(case_id, grantee_user_id)
    WHERE revoked_at IS NULL;

COMMENT ON TABLE case_access_grants IS
  'PRD LR-002 purpose limitation. No implicit cross-jurisdiction visibility.
   A minimum justification length is enforced so grants cannot be rubber-
   stamped with a single character.';

-- ───────────────────────────────────────────────────────────────────────────
-- sessions
-- ───────────────────────────────────────────────────────────────────────────
CREATE TABLE sessions (
    id                  UUID PRIMARY KEY,
    user_id             UUID NOT NULL REFERENCES users(id),
    issued_at           TIMESTAMPTZ NOT NULL DEFAULT now(),
    expires_at          TIMESTAMPTZ NOT NULL,
    last_reauth_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    source_ip           INET NOT NULL,
    user_agent_digest   BYTEA NOT NULL,   -- hash, not raw UA string
    mfa_satisfied       BOOLEAN NOT NULL DEFAULT FALSE,
    revoked_at          TIMESTAMPTZ
);
CREATE INDEX ix_sessions_user_active ON sessions(user_id)
    WHERE revoked_at IS NULL;

5.  POSTGRESQL — CASE MANAGEMENT
═════════════════════════════════════════════════════════════════════════════

CREATE TABLE cases (
    id                      UUID PRIMARY KEY,
    case_reference          TEXT        NOT NULL UNIQUE,
        -- format PHM-<YYYY>-<STATE>-<NNNNNN>, generated by sequence+trigger
    organization_id         UUID        NOT NULL REFERENCES organizations(id),
    created_by              UUID        NOT NULL REFERENCES users(id),
    assigned_to             UUID        REFERENCES users(id),
    supervisor_id           UUID        REFERENCES users(id),

    title                   TEXT        NOT NULL,
    case_type               case_type_t NOT NULL,
    status                  case_status_t NOT NULL DEFAULT 'DRAFT',
    priority                SMALLINT    NOT NULL DEFAULT 3,  -- 1 highest

    -- LAWFUL AUTHORITY GATE (PRD LR-001) ------------------------------------
    fir_number              TEXT,
    ncrp_acknowledgement    TEXT,
    written_authority_ref   TEXT,
    authority_recorded_at   TIMESTAMPTZ,
    authority_recorded_by   UUID REFERENCES users(id),

    -- victim/loss context (no personal data of the victim stored here) ------
    reported_loss_base      NUMERIC(78,0),   -- INR paise as integer
    reported_loss_currency  CHAR(3) DEFAULT 'INR',
    incident_occurred_at    TIMESTAMPTZ,
    complaint_filed_at      TIMESTAMPTZ,

    legal_hold              BOOLEAN     NOT NULL DEFAULT FALSE,
    retention_expires_at    TIMESTAMPTZ,

    closed_at               TIMESTAMPTZ,
    closure_reason          TEXT,
    created_at              TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at              TIMESTAMPTZ NOT NULL DEFAULT now(),

    CONSTRAINT ck_case_authority_present CHECK (
        status = 'DRAFT'
        OR fir_number IS NOT NULL
        OR ncrp_acknowledgement IS NOT NULL
        OR written_authority_ref IS NOT NULL
    ),
    CONSTRAINT ck_case_priority CHECK (priority BETWEEN 1 AND 5),
    CONSTRAINT ck_case_closed CHECK (
        (status IN ('CLOSED','ARCHIVED')) = (closed_at IS NOT NULL)
    )
);

CREATE INDEX ix_cases_org_status ON cases(organization_id, status);
CREATE INDEX ix_cases_assigned   ON cases(assigned_to)
    WHERE status NOT IN ('CLOSED','ARCHIVED');
CREATE INDEX ix_cases_legal_hold ON cases(id) WHERE legal_hold;
CREATE INDEX ix_cases_retention  ON cases(retention_expires_at)
    WHERE legal_hold = FALSE AND retention_expires_at IS NOT NULL;

COMMENT ON CONSTRAINT ck_case_authority_present ON cases IS
  'Hard enforcement of PRD LR-001: a case cannot leave DRAFT — and therefore
   cannot run a trace — without a recorded lawful authority reference.';

ALTER TABLE case_access_grants
    ADD CONSTRAINT fk_grants_case FOREIGN KEY (case_id) REFERENCES cases(id);

-- ───────────────────────────────────────────────────────────────────────────
-- case_seed_addresses
-- ───────────────────────────────────────────────────────────────────────────
CREATE TABLE case_seed_addresses (
    id                  UUID PRIMARY KEY,
    case_id             UUID NOT NULL REFERENCES cases(id) ON DELETE RESTRICT,
    address_id          UUID NOT NULL,      -- FK to addresses (§6)
    added_by            UUID NOT NULL REFERENCES users(id),
    seed_role           TEXT NOT NULL,      -- PRIMARY_SUSPECT |
                                            -- VICTIM_SOURCE | SECONDARY
    source_of_address   TEXT NOT NULL,      -- COMPLAINT | BANK_RECORD |
                                            -- DEVICE_FORENSICS | OSINT
    notes               TEXT,
    added_at            TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (case_id, address_id)
);
CREATE INDEX ix_seed_addr_address ON case_seed_addresses(address_id);

COMMENT ON COLUMN case_seed_addresses.source_of_address IS
  'Provenance of the seed itself matters evidentially — a court will ask how
   the investigator obtained the address.';

-- ───────────────────────────────────────────────────────────────────────────
-- case_events : the human-visible case timeline
-- ───────────────────────────────────────────────────────────────────────────
CREATE TABLE case_events (
    id                  UUID PRIMARY KEY,
    case_id             UUID NOT NULL REFERENCES cases(id),
    actor_user_id       UUID REFERENCES users(id),
    actor_kind          actor_kind_t NOT NULL DEFAULT 'HUMAN',
    event_type          TEXT NOT NULL,
    summary             TEXT NOT NULL,
    detail              JSONB NOT NULL DEFAULT '{}'::jsonb,
    related_entity_type TEXT,
    related_entity_id   UUID,
    occurred_at         TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX ix_case_events_case_time ON case_events(case_id, occurred_at DESC);

-- ───────────────────────────────────────────────────────────────────────────
-- case_attachments
-- ───────────────────────────────────────────────────────────────────────────
CREATE TABLE case_attachments (
    id                  UUID PRIMARY KEY,
    case_id             UUID NOT NULL REFERENCES cases(id),
    uploaded_by         UUID NOT NULL REFERENCES users(id),
    file_name           TEXT NOT NULL,
    mime_type           TEXT NOT NULL,
    size_bytes          BIGINT NOT NULL,
    sha256              BYTEA NOT NULL,
    object_key          TEXT NOT NULL,
    virus_scan_status   TEXT NOT NULL DEFAULT 'PENDING',
    uploaded_at         TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT ck_attach_size CHECK (size_bytes > 0),
    CONSTRAINT ck_attach_hash CHECK (octet_length(sha256) = 32)
);

CREATE TABLE chains (
    id                      SMALLINT PRIMARY KEY,   -- stable internal id
    chain_key               TEXT NOT NULL UNIQUE,   -- 'bitcoin','ethereum',...
    display_name            TEXT NOT NULL,
    chain_model             chain_model_t NOT NULL,
    native_asset_symbol     TEXT NOT NULL,
    caip2_identifier        TEXT,                   -- e.g. 'eip155:1'

COMMENT ON COLUMN chains.graph_shard_key IS
  'Consistent-hash routing key. Adding a chain adds a shard; it does NOT
   rebalance existing shards (PRD FR-GRF-002).';

-- ───────────────────────────────────────────────────────────────────────────
-- chain_finality_configs : confirmation-depth gate, config-driven (FR-ING-004)
-- ───────────────────────────────────────────────────────────────────────────
CREATE TABLE chain_finality_configs (
    id                      UUID PRIMARY KEY,
    chain_id                SMALLINT NOT NULL REFERENCES chains(id),
    min_confirmations       INT      NOT NULL,
    finality_semantics      TEXT     NOT NULL,  -- PROBABILISTIC |
                                                -- ECONOMIC_FINALITY |

-- These three tables are the evidentiary core. INSERT-only. Never UPDATE.
-- Partitioned by chain_id (LIST) then by block-height range where volume
-- requires it. Partitioning by chain also gives clean per-chain retention
-- and lets a chain be detached wholesale if it is retired.

-- ───────────────────────────────────────────────────────────────────────────
-- blocks
-- ───────────────────────────────────────────────────────────────────────────

   marked REORGED and triggers a P1 case alert (PRD US-ING-004 AC3).';

-- ───────────────────────────────────────────────────────────────────────────
-- transactions
-- ───────────────────────────────────────────────────────────────────────────
CREATE TABLE transactions (

    nonce                   BIGINT,
    is_contract_creation    BOOLEAN NOT NULL DEFAULT FALSE,
    input_selector          BYTEA,          -- first 4 bytes of calldata

    )

CREATE TABLE transactions_bitcoin  PARTITION OF transactions FOR VALUES IN (1);

  'SHA-256 over the canonical field subset {tx_hash, block_height, block_hash,
   from, to, value, asset, timestamp}. Two providers agree iff their digests
   match. This makes cross-validation a constant-time comparison rather than
   a field-by-field diff at query time (PRD US-ING-003 AC2).';

-- ───────────────────────────────────────────────────────────────────────────
-- transfers : the value-movement grain. THIS is what becomes a graph edge.
-- ───────────────────────────────────────────────────────────────────────────
-- One transaction may produce many transfers: native value + N token
-- transfers + M internal calls. The graph edge is the transfer, not the tx.
-- Getting this grain wrong is the single most common modelling error in
-- blockchain forensics systems.

CREATE TABLE transfers (
    id                      UUID        NOT NULL,
    chain_id                SMALLINT    NOT NULL,
    transaction_id          UUID        NOT NULL,
    tx_hash                 BYTEA       NOT NULL,   -- denormalised for joins
    block_height            BIGINT      NOT NULL,
    block_timestamp         TIMESTAMPTZ NOT NULL,

    transfer_index          INT         NOT NULL,   -- ordinal within the tx
    transfer_kind           TEXT        NOT NULL,   -- NATIVE | TOKEN |
                                                    -- INTERNAL | UTXO_FLOW |
                                                    -- FEE | BRIDGE_IN |
                                                    -- BRIDGE_OUT
    from_address_id         UUID,                   -- NULL on mint/coinbase
    to_address_id           UUID,                   -- NULL on burn
    asset_id                UUID        NOT NULL,
    value_base              NUMERIC(78,0) NOT NULL,

    -- UTXO linkage
    utxo_spent_tx_hash      BYTEA,
    utxo_spent_vout         INT,
    utxo_created_vout       INT,

    -- heuristic annotations (inference, kept separate from fact)
    is_change_output        BOOLEAN,
    change_heuristic        TEXT,       -- ADDRESS_REUSE | ROUND_NUMBER |
                                        -- SCRIPT_TYPE_MATCH | POSITION
    cospend_cluster_id      UUID,

    validation_status       validation_status_t NOT NULL DEFAULT 'UNVERIFIED',
    is_pruned               BOOLEAN     NOT NULL DEFAULT FALSE,
    prune_reason            TEXT,
    ingest_run_id           UUID        NOT NULL,
    ingested_at             TIMESTAMPTZ NOT NULL DEFAULT now(),

    PRIMARY KEY (chain_id, id),
    CONSTRAINT ck_transfer_value_nonneg CHECK (value_base >= 0),
    CONSTRAINT ck_transfer_endpoints CHECK (
        from_address_id IS NOT NULL OR to_address_id IS NOT NULL),
    CONSTRAINT ck_prune_reason CHECK (
        (is_pruned = FALSE) OR (prune_reason IS NOT NULL))
) PARTITION BY LIST (chain_id);

CREATE TABLE transfers_bitcoin  PARTITION OF transfers FOR VALUES IN (1);
CREATE TABLE transfers_ethereum PARTITION OF transfers FOR VALUES IN (2);
CREATE TABLE transfers_bnb      PARTITION OF transfers FOR VALUES IN (3);
CREATE TABLE transfers_polygon  PARTITION OF transfers FOR VALUES IN (4);
CREATE TABLE transfers_tron     PARTITION OF transfers FOR VALUES IN (5);
CREATE TABLE transfers_solana   PARTITION OF transfers FOR VALUES IN (6);

CREATE UNIQUE INDEX ux_transfers_natural
    ON transfers (chain_id, tx_hash, transfer_index);
CREATE INDEX ix_transfers_from_time
    ON transfers (from_address_id, block_timestamp DESC)
    WHERE is_pruned = FALSE;
CREATE INDEX ix_transfers_to_time
    ON transfers (to_address_id, block_timestamp DESC)
    WHERE is_pruned = FALSE;
CREATE INDEX ix_transfers_asset_value
    ON transfers (asset_id, value_base DESC);
CREATE INDEX ix_transfers_cluster
    ON transfers (cospend_cluster_id)
    WHERE cospend_cluster_id IS NOT NULL;
CREATE INDEX ix_transfers_utxo_spent
    ON transfers (utxo_spent_tx_hash, utxo_spent_vout)
    WHERE utxo_spent_tx_hash IS NOT NULL;

COMMENT ON TABLE transfers IS
  'The unit of value movement and the unit of graph edge. Note that
   is_pruned is a SOFT flag (PRD US-TPP-005 AC2) — pruning never deletes
   evidence, it only excludes it from the default view and from search.';

COMMENT ON COLUMN transfers.change_heuristic IS
  'Which heuristic inferred this as a change output. Recorded because a
   defence expert will challenge the inference, and "the tool said so" is
   not an answer. Naming the heuristic makes the inference contestable and
   therefore defensible.';

-- ───────────────────────────────────────────────────────────────────────────
-- cospend_clusters : UTXO multi-input clustering result (FR-ING-003)
-- ───────────────────────────────────────────────────────────────────────────
CREATE TABLE cospend_clusters (
    id                      UUID PRIMARY KEY,
    chain_id                SMALLINT NOT NULL REFERENCES chains(id),
    member_count            INT NOT NULL,
    representative_addr_id  UUID NOT NULL,
    heuristic_version       TEXT NOT NULL,
    computed_at             TIMESTAMPTZ NOT NULL DEFAULT now(),
    ingest_run_id           UUID NOT NULL
);

CREATE TABLE cospend_cluster_members (
    cluster_id              UUID NOT NULL REFERENCES cospend_clusters(id),
    address_id              UUID NOT NULL,
    evidence_tx_hash        BYTEA NOT NULL,
    PRIMARY KEY (cluster_id, address_id)
);
CREATE INDEX ix_cospend_member_addr ON cospend_cluster_members(address_id);

COMMENT ON TABLE cospend_clusters IS
  'Co-spend clustering is an INFERENCE, not a fact. It is stored separately
   from transfers so a dossier can present it as "heuristic linkage with
   stated assumptions" rather than as ledger truth. CoinJoin and PayJoin
   transactions violate the co-spend assumption; the heuristic_version field
   records which exclusion rules were applied.';

9.  POSTGRESQL — TEMPORAL ANALYSIS ARTEFACTS
═════════════════════════════════════════════════════════════════════════════

CREATE TABLE temporal_profiles (
    id                      UUID PRIMARY KEY,
    address_id              UUID NOT NULL,
    chain_id                SMALLINT NOT NULL,
    trace_id                UUID,               -- NULL if computed globally
    model_version_id        UUID NOT NULL,

    -- Hawkes parameters: lambda(t) = mu + SUM alpha * exp(-beta*(t - t_i))
    hawkes_mu               DOUBLE PRECISION,   -- background intensity
    hawkes_alpha            DOUBLE PRECISION,   -- excitation magnitude
    hawkes_beta             DOUBLE PRECISION,   -- decay rate
    branching_ratio         DOUBLE PRECISION,   -- alpha/beta; >=1 => explosive
    log_likelihood          DOUBLE PRECISION,
    fit_event_count         INT NOT NULL,
    fit_window_start        TIMESTAMPTZ,
    fit_window_end          TIMESTAMPTZ,

    dominant_pattern        temporal_pattern_t NOT NULL,
    pattern_scores          JSONB NOT NULL,     -- {"PEEL_CHAIN":0.81,...}
    burst_count             INT NOT NULL DEFAULT 0,
    median_interarrival_s   DOUBLE PRECISION,
    interarrival_cv         DOUBLE PRECISION,   -- coeff. of variation

    computed_at             TIMESTAMPTZ NOT NULL DEFAULT now(),
    parameters_json         JSONB NOT NULL,     -- full hyperparameter set

    CONSTRAINT ck_branching CHECK (
        branching_ratio IS NULL OR branching_ratio >= 0)
);
CREATE INDEX ix_temporal_addr ON temporal_profiles(address_id, computed_at DESC);
CREATE INDEX ix_temporal_trace ON temporal_profiles(trace_id);
CREATE INDEX ix_temporal_pattern ON temporal_profiles(dominant_pattern);

COMMENT ON COLUMN temporal_profiles.branching_ratio IS
  'alpha/beta. Values approaching or exceeding 1 indicate a self-sustaining
   cascade — the statistical signature of automated peel chains and
   structuring. Values near 0 indicate background-dominated organic activity.
   Stored explicitly so the dossier can state the numeric basis for a
   "bot-driven" claim rather than asserting it.';

COMMENT ON COLUMN temporal_profiles.fit_event_count IS
  'A Hawkes fit on fewer than ~30 events is not trustworthy. Below the
   configured minimum, dominant_pattern is set to INSUFFICIENT_DATA rather
   than reporting a confident-looking but meaningless fit.';

CREATE TABLE temporal_bursts (
    id                      UUID PRIMARY KEY,
    temporal_profile_id     UUID NOT NULL REFERENCES temporal_profiles(id),
    burst_start_at          TIMESTAMPTZ NOT NULL,
    burst_end_at            TIMESTAMPTZ NOT NULL,
    event_count             INT NOT NULL,
    peak_intensity          DOUBLE PRECISION,
    total_value_base        NUMERIC(78,0),
    pattern                 temporal_pattern_t NOT NULL,
    CONSTRAINT ck_burst_window CHECK (burst_end_at >= burst_start_at)
);
CREATE INDEX ix_bursts_profile ON temporal_bursts(temporal_profile_id);

10.  POSTGRESQL — CLASSIFICATION ARTEFACTS

CREATE TABLE address_classifications (
    id                      UUID PRIMARY KEY,
    address_id              UUID NOT NULL,
    chain_id                SMALLINT NOT NULL,
    trace_id                UUID,               -- NULL = global background job

    predicted_class         node_class_t NOT NULL,
    class_probabilities     JSONB NOT NULL,     -- full vector, FR-CLS-004
    max_probability         NUMERIC(5,4) NOT NULL,
    is_abstained            BOOLEAN NOT NULL DEFAULT FALSE,
    is_absorption_state     BOOLEAN NOT NULL DEFAULT FALSE,

    -- model lineage
    hgt_model_version_id    UUID,
    rgcn_model_version_id   UUID,
    tgn_model_version_id    UUID,
    calibrator_version_id   UUID,
    feature_set_version     TEXT NOT NULL,

    -- corroborating independent signals, kept SEPARATE from the model score
    bytecode_signature_id   UUID REFERENCES contract_signatures(id),
    registry_match_vasp_id  UUID,               -- FK to vasp_entities
    external_label_source   TEXT,               -- OFAC | public tag set | etc

    -- explainability (FR-OBS/US-OBS-017)
    top_features            JSONB,              -- [{feature, contribution}]
    attention_summary       JSONB,              -- per-relation attention mass

    -- human override (US-CLS-008)
    is_human_override       BOOLEAN NOT NULL DEFAULT FALSE,
    overridden_from_class   node_class_t,
    override_justification  TEXT,
    overridden_by           UUID REFERENCES users(id),
    overridden_at           TIMESTAMPTZ,

    superseded_by_id        UUID REFERENCES address_classifications(id),
    computed_at             TIMESTAMPTZ NOT NULL DEFAULT now(),

    CONSTRAINT ck_cls_prob CHECK (max_probability BETWEEN 0 AND 1),
    CONSTRAINT ck_cls_abstain CHECK (
        (is_abstained = FALSE) OR (predicted_class = 'UNKNOWN')),
    CONSTRAINT ck_cls_override CHECK (
        (is_human_override = FALSE) OR
        (override_justification IS NOT NULL
         AND length(override_justification) >= 20
         AND overridden_by IS NOT NULL
         AND overridden_from_class IS NOT NULL))
);

CREATE INDEX ix_cls_address_current ON address_classifications(address_id)
    WHERE superseded_by_id IS NULL;
CREATE INDEX ix_cls_trace ON address_classifications(trace_id);
CREATE INDEX ix_cls_class ON address_classifications(predicted_class)
    WHERE superseded_by_id IS NULL;
CREATE INDEX ix_cls_absorption ON address_classifications(address_id)
    WHERE is_absorption_state AND superseded_by_id IS NULL;
CREATE INDEX ix_cls_overrides ON address_classifications(overridden_by)
    WHERE is_human_override;

COMMENT ON TABLE address_classifications IS
  'Append-only and versioned via superseded_by_id. A newer model NEVER
   mutates an existing row, because a dossier already generated cites a
   specific classification row id and must remain reproducible forever
   (PRD FR-CLS-007, MG-006).';

COMMENT ON COLUMN address_classifications.bytecode_signature_id IS
  'Independent corroboration kept structurally separate from the learned
   score, per FR-CLS-006. Folding a deterministic signature match into a
   model probability would make the resulting number uninterpretable.';

-- ───────────────────────────────────────────────────────────────────────────
-- classification_label_candidates : override → training label pipeline

CREATE TABLE classification_label_candidates (

    proposed_label          node_class_t NOT NULL,
    proposed_by             UUID NOT NULL REFERENCES users(id),
    proposed_at             TIMESTAMPTZ NOT NULL DEFAULT now(),
    curator_status          TEXT NOT NULL DEFAULT 'PENDING', -- APPROVED |

    curator_id              UUID REFERENCES users(id),
    curator_note            TEXT,
    reviewed_at             TIMESTAMPTZ,
    included_in_dataset     TEXT       -- dataset version if accepted
);

COMMENT ON TABLE classification_label_candidates IS
  'PRD RSK-011: without this curator gate, the model would train on its own
   corrected mistakes in a closed feedback loop, silently learning the biases

CREATE TABLE merkle_proofs (

-- §12.4  HONEST PROOF SEMANTICS — read this before implementing.
--
-- COMMENT ON TABLE merkle_proofs:
COMMENT ON TABLE merkle_proofs IS
  'Per-chain proof semantics differ and MUST NOT be conflated:
   • BITCOIN / TRON — a genuine transaction Merkle branch under the block
     header merkle_root. This is a true inclusion proof.
   • ETHEREUM / BNB / POLYGON — the block header commits to a
     Merkle-Patricia transactions/receipts trie, not a plain Merkle tree.
     The proof is an MPT branch. Calling it a "Merkle proof" loosely is
     acceptable in prose; storing it with the wrong proof_kind is not.
   • SOLANA — has no per-transaction Merkle inclusion proof of the Bitcoin
     kind. proof_kind = SOLANA_ENTRY_ATTESTATION and alternative_mechanism
     MUST describe what is actually being asserted.
   PRD US-EVD-009 AC3 requires the dossier to state the alternative
   mechanism honestly rather than present a misleading proof. This column
   design forces that honesty at the schema level.';

-- ── APPEND-ONLY ENFORCEMENT (PRD LAW 4 / SR-009) ──────────────────────────
CREATE OR REPLACE FUNCTION fn_audit_immutable()
RETURNS TRIGGER LANGUAGE plpgsql AS $$
BEGIN
    RAISE EXCEPTION
      'audit_log is append-only: % attempted on entry %', TG_OP, OLD.id
      USING ERRCODE = 'insufficient_privilege';
END; $$;

CREATE TRIGGER trg_audit_no_update
    BEFORE UPDATE ON audit_log
    FOR EACH ROW EXECUTE FUNCTION fn_audit_immutable();

CREATE TRIGGER trg_audit_no_delete
    BEFORE DELETE ON audit_log
    FOR EACH ROW EXECUTE FUNCTION fn_audit_immutable();

REVOKE UPDATE, DELETE, TRUNCATE ON audit_log FROM PUBLIC;

-- ── HASH CHAIN CONSTRUCTION ───────────────────────────────────────────────
CREATE OR REPLACE FUNCTION fn_audit_chain()
RETURNS TRIGGER LANGUAGE plpgsql AS $$
DECLARE
    v_prev BYTEA;
BEGIN
    SELECT entry_hash INTO v_prev
      FROM audit_log ORDER BY id DESC LIMIT 1;

    NEW.prev_entry_hash := v_prev;
    NEW.entry_hash := digest(
        coalesce(encode(v_prev,'hex'),'GENESIS')
        || NEW.occurred_at::text
        || coalesce(NEW.actor_user_id::text,'-')
        || NEW.action
        || NEW.entity_type
        || coalesce(NEW.entity_id::text,'-')
        || encode(NEW.payload_digest,'hex'),
        'sha256');
    RETURN NEW;
END; $$;

CREATE TRIGGER trg_audit_chain
    BEFORE INSERT ON audit_log
    FOR EACH ROW EXECUTE FUNCTION fn_audit_chain();

COMMENT ON TABLE audit_log IS
  'Each entry commits to its predecessor. Deleting or altering any historical
   entry breaks every subsequent hash, making silent tampering detectable by
   the daily verification job (PRD US-ADM-015 AC1/AC3). Note the chain is
   strictly serialised on insert — this is a deliberate throughput trade
   accepted because audit integrity outranks audit write speed.';

-- ── DAILY INTEGRITY VERIFICATION ──────────────────────────────────────────
CREATE OR REPLACE FUNCTION fn_verify_audit_chain(p_from BIGINT DEFAULT 1)
RETURNS TABLE (broken_at BIGINT, expected BYTEA, found BYTEA)
LANGUAGE plpgsql AS $$
DECLARE r RECORD; v_prev BYTEA; v_calc BYTEA;
BEGIN
    SELECT prev_entry_hash INTO v_prev FROM audit_log WHERE id = p_from;
    FOR r IN SELECT * FROM audit_log WHERE id >= p_from ORDER BY id LOOP
        v_calc := digest(
            coalesce(encode(v_prev,'hex'),'GENESIS')
            || r.occurred_at::text
            || coalesce(r.actor_user_id::text,'-')
            || r.action || r.entity_type
            || coalesce(r.entity_id::text,'-')
            || encode(r.payload_digest,'hex'), 'sha256');
        IF v_calc <> r.entry_hash THEN
            broken_at := r.id; expected := v_calc; found := r.entry_hash;
            RETURN NEXT;
        END IF;
        v_prev := r.entry_hash;
    END LOOP;
END; $$;

CREATE TABLE audit_chain_checkpoints (
    id                      BIGSERIAL PRIMARY KEY,
    checked_through_id      BIGINT NOT NULL,
    chain_head_hash         BYTEA NOT NULL,
    is_intact               BOOLEAN NOT NULL,
    broken_at_id            BIGINT,

    external_anchor_ref     TEXT   -- optional: published head hash reference
);

     finding is rejected on sight.

19.  POSTGRESQL — CONSTRAINTS, TRIGGERS & INVARIANTS
═════════════════════════════════════════════════════════════════════════════

  INVARIANT 1 — Lawful authority precedes traces.
    Enforced by ck_case_authority_present plus an application check that a
    trace cannot be launched on a case in DRAFT.

  INVARIANT 2 — No dispatch without approval and scope check.
    Enforced by ck_disc_dispatch_gate.

  INVARIANT 3 — Ledger tables are insert-only.
    REVOKE UPDATE, DELETE ON blocks, transactions, transfers FROM app_role;
    Corrections are made by inserting a superseding row and marking the old
    one via validation_status, never by mutation.

  INVARIANT 4 — A dossier's cited transactions must be final.
    Trigger fn_check_dossier_finality() raises if any cited hop has
    validation_status IN ('PENDING_FINALITY','REORGED').

CREATE OR REPLACE FUNCTION fn_check_dossier_finality()
RETURNS TRIGGER LANGUAGE plpgsql AS $$
DECLARE v_bad INT;
BEGIN
    SELECT count(*) INTO v_bad
      FROM trace_path_hops h
     WHERE h.trace_path_id = NEW.trace_path_id
       AND h.validation_status IN ('PENDING_FINALITY','REORGED');
    IF v_bad > 0 THEN
        RAISE EXCEPTION
          'Cannot generate dossier: % hop(s) are not final', v_bad;
    END IF;
    RETURN NEW;
END; $$;

CREATE TRIGGER trg_dossier_finality
    BEFORE INSERT ON dossiers
    FOR EACH ROW EXECUTE FUNCTION fn_check_dossier_finality();

  INVARIANT 5 — Human override requires justification.
    Enforced by ck_cls_override (length >= 20 characters).

  INVARIANT 6 — Exactly one ACTIVE model per family.
    Enforced by ux_model_active partial unique index.

  INVARIANT 7 — Monetary values never lose precision.
    Enforced by NUMERIC(78,0) typing; a CI lint rejects FLOAT/REAL/DOUBLE
    columns whose names match /(value|amount|balance|fee)/.

  INVARIANT 8 — updated_at maintained automatically.

CREATE OR REPLACE FUNCTION fn_touch_updated_at()
RETURNS TRIGGER LANGUAGE plpgsql AS $$
BEGIN NEW.updated_at := now(); RETURN NEW; END; $$;
-- Applied to: organizations, users, cases, addresses (cache fields).

  INVARIANT 9 — Case reference generation is gapless and unique per year.
    Sequence per (year, state_code) with a formatting trigger.

  INVARIANT 10 — Deleting a case is impossible while evidence exists.
    ON DELETE RESTRICT on every child FK; archival is a status change, never
    a DELETE. Physical deletion happens only through the retention job, and
    never while legal_hold is TRUE.

20.  POSTGRESQL — PARTITIONING & RETENTION
═════════════════════════════════════════════════════════════════════════════

20.1  PARTITIONING
  blocks / transactions / transfers   → LIST by chain_id (level 1)
                                        RANGE by block_height (level 2 where
                                        a chain exceeds ~200M rows)
  audit_log                           → RANGE by occurred_at, monthly
  case_events                         → RANGE by occurred_at, quarterly

  Sub-partitioning by height rather than by time is deliberate: block height
  is monotonic and gap-free, timestamps are not strictly monotonic on some
  chains, and height-ranged partitions align with how backfills are run.

20.2  RETENTION MATRIX
  ┌──────────────────────┬──────────────────────────────────────────────────┐
  │ Data                 │ Policy                                           │
  ├──────────────────────┼──────────────────────────────────────────────────┤
  │ audit_log            │ Never deleted. Archived to WORM after 24 months.  │
  │ evidence_items       │ Retained for case retention period + legal hold.  │
  │ dossiers             │ Same as evidence; never deleted under legal hold. │
  │ ledger facts         │ Retained indefinitely (public data, re-fetchable).│
  │ classifications      │ Retained; cheap and needed for reproducibility.   │
  │ provider raw payloads│ 90 days in object store, then digest-only.        │
  │ sessions             │ 30 days.                                          │
  │ provider_health      │ 13 months rolled up to monthly aggregates.        │
  │ closed cases         │ Per agency records policy (config-driven).        │
  └──────────────────────┴──────────────────────────────────────────────────┘

20.3  LEGAL HOLD
  A case with legal_hold = TRUE is excluded from every retention job. The
  retention job MUST log the count of records it skipped for legal hold so
  the exclusion is itself auditable.

21.  NEO4J — GRAPH MODEL
═════════════════════════════════════════════════════════════════════════════

21.1  WHY A SEPARATE ENGINE
  The core query is: "from this node, find the shortest weighted path to any
  node satisfying a label predicate, stopping at absorption states, up to
  depth 12, on a graph where some nodes have 500k+ neighbours." That is a
  native graph traversal. In SQL it is a recursive CTE that will not return.

21.2  NODE LABELS

  (:Address)                    -- base label, always present
    chain_key            STRING  (indexed, shard-local constant)
    address              STRING  (canonical form)
    address_uid          STRING  (= chain_key + ':' + address, unique)
    pg_address_id        STRING  (UUID back-reference to PostgreSQL)
    is_contract          BOOLEAN
    degree_in            INTEGER
    degree_out           INTEGER
    is_high_degree       BOOLEAN
    first_activity_ts    INTEGER (epoch seconds)
    last_activity_ts     INTEGER
    -- cached classification (denormalised for traversal-time filtering)
    class                STRING
    class_probability    FLOAT
    is_absorption        BOOLEAN
    class_model_version  STRING
    class_cached_at      INTEGER
    temporal_pattern     STRING
    branching_ratio      FLOAT

  Secondary labels applied additively for fast label-scan filtering:
    :VASP  :Mixer  :Bridge  :DEX  :Mule  :Staking  :Contract  :Sanctioned
    :Absorption   :HighDegree   :Seed

  (:Vasp)                       -- entity node, not an address
    vasp_uid             STRING (unique)
    legal_name           STRING
    jurisdiction         STRING
    fiu_registered       BOOLEAN
    sahyog_onboarded     BOOLEAN

  (:Asset)
    asset_uid            STRING (unique: chain_key + ':' + contract|native)
    symbol               STRING
    decimals             INTEGER
    is_stablecoin        BOOLEAN

  (:Block)                      -- sparse; only for cited evidence anchors
    chain_key            STRING
    height               INTEGER
    block_hash           STRING

21.3  RELATIONSHIP TYPES

  (:Address)-[:SENT_NATIVE    ]->(:Address)
  (:Address)-[:SENT_TOKEN     ]->(:Address)
  (:Address)-[:INTERNAL_CALL  ]->(:Address)
  (:Address)-[:UTXO_FLOW      ]->(:Address)
  (:Address)-[:BRIDGED_TO     ]->(:Address)   -- cross-shard, typed
  (:Address)-[:COSPEND_WITH   ]-(:Address)    -- undirected inference edge
  (:Address)-[:DEPOSIT_OF     ]->(:Vasp)
  (:Address)-[:CHANGE_OF      ]->(:Address)   -- inference edge

  RELATIONSHIP PROPERTIES (on all transfer-type relationships):
    transfer_uid        STRING  (unique; = chain:txhash:index)
    tx_hash             STRING
    block_height        INTEGER
    block_ts            INTEGER
    asset_uid           STRING
    value_base          STRING   -- decimal string; Neo4j has no uint256
    value_normalised    FLOAT    -- for weighting ONLY, never for evidence
    weight              FLOAT    -- precomputed search weight
    time_decay          FLOAT
    is_pruned           BOOLEAN
    prune_reason        STRING
    validation_status   STRING
    confirmations       INTEGER
    pg_transfer_id      STRING

  CRITICAL MODELLING NOTE ON value_base:
    Neo4j has no arbitrary-precision integer type. Exact values are stored as
    DECIMAL STRINGS and are used only for display/back-reference. All exact
    arithmetic — every number that reaches a dossier — is done in PostgreSQL
    against NUMERIC(78,0). value_normalised (a float) exists solely to weight
    traversal. Using a float value in an evidentiary computation is a
    correctness bug, and the field name is chosen to make that obvious in
    code review.

  INFERENCE EDGES ARE TYPED SEPARATELY:
    COSPEND_WITH and CHANGE_OF are inferences, not observed transfers. They
    carry `heuristic` and `heuristic_version` properties and are excluded by
    default from evidentiary path construction. A path that relies on an
    inference edge is flagged in the dossier as heuristic-dependent.

21.4  BRIDGE / CROSS-SHARD MODEL
  Each chain lives in its own database (shard). A cross-chain hop is
  represented in BOTH shards:
    source shard:  (:Address {chain:'ethereum'})-[:BRIDGED_TO
                     {counterpart_chain:'polygon',
                      counterpart_address_uid:'polygon:0x...',
                      correlation_method:'EVENT_LOG',
                      correlation_confidence: 0.82}]->(:Address:BridgeStub)
    dest shard:    a mirrored stub in the opposite direction.
  The traversal engine detects a BridgeStub, resolves the counterpart via the
  PostgreSQL bridge_index, and continues the search in the destination shard.
  The stub keeps each shard self-consistent without cross-database traversal,
  which Neo4j does not support natively.

23.  NEO4J — CANONICAL CYPHER QUERY LIBRARY
═════════════════════════════════════════════════════════════════════════════

// Q1 — SEED NEIGHBOURHOOD EXPANSION (bounded, pruning-aware)
MATCH (seed:Address {address_uid: $seed_uid})
CALL apoc.path.expandConfig(seed, {
    relationshipFilter: 'SENT_NATIVE>|SENT_TOKEN>|UTXO_FLOW>|INTERNAL_CALL>',
    labelFilter:        '-Absorption',      // stop at absorbing nodes
    minLevel: 1,
    maxLevel: $max_depth,
    limit:    $node_budget,
    bfs:      false
}) YIELD path
WITH path, relationships(path) AS rels
WHERE none(r IN rels WHERE r.is_pruned = true)
  AND all(r IN rels WHERE r.validation_status <> 'PENDING_FINALITY')
RETURN path
LIMIT $path_limit;

// NOTE: labelFilter '-Absorption' is the mechanical implementation of
// classify-then-search. The classifier writes the :Absorption label before
// this query runs; the traversal therefore never enters a hot wallet's
// 500k-edge neighbourhood. This single line is the answer to PS gap #1.


// Q2 — WEIGHTED SHORTEST PATH TO NEAREST CUSTODIAL VASP
MATCH (seed:Address {address_uid: $seed_uid})
MATCH (target:Address)
WHERE target:VASP AND target.is_absorption = true
CALL apoc.algo.dijkstra(seed, target,
    'SENT_NATIVE>|SENT_TOKEN>|UTXO_FLOW>|BRIDGED_TO>', 'weight')
YIELD path, weight
RETURN path, weight,
       length(path)                      AS hop_count,
       [n IN nodes(path) | n.address]    AS address_chain,
       [r IN relationships(path) | r.tx_hash] AS tx_chain
ORDER BY weight ASC
LIMIT $top_k;


// Q3 — PERSONALISED PAGERANK TO RESTRICT THE FRONTIER
CALL gds.pageRank.stream('phantasm_subgraph', {
    maxIterations: 20,
    dampingFactor: 0.85,
    sourceNodes: [$seed_node_id],
    relationshipWeightProperty: 'weight'
})
YIELD nodeId, score
WITH gds.util.asNode(nodeId) AS n, score
WHERE score > $ppr_threshold
RETURN n.address_uid AS uid, n.class AS class, score
ORDER BY score DESC
LIMIT $frontier_size;


// Q4 — HIGH-DEGREE GUARD (run before any expansion)
MATCH (a:Address {address_uid: $uid})
RETURN a.degree_in + a.degree_out AS degree,
       a.is_high_degree           AS is_hub,
       a.class                    AS class,
       a.is_absorption            AS absorbs;
// If is_hub AND NOT absorbs AND class = 'UNKNOWN' → force classification
// before expanding. Expanding an unclassified hub is the failure mode that
// kills naive implementations.


// Q5 — MIXER/BRIDGE ENCOUNTER DETECTION ALONG A PATH
MATCH path = (seed:Address {address_uid: $seed_uid})-[*1..12]->(t:Address)
WHERE t.is_absorption = true
WITH path, [n IN nodes(path) WHERE n:Mixer OR n:Bridge] AS obfuscators
RETURN path,
       size(obfuscators)                      AS obfuscator_count,
       [n IN obfuscators | n.address_uid]     AS obfuscator_uids;
// obfuscator_count > 0 downgrades path confidence and, for :Mixer, triggers
// the TERMINATED_AT_OBFUSCATOR flow (PRD Journey B).


// Q6 — CO-SPEND CLUSTER RESOLUTION (UTXO shards only)
MATCH (a:Address {address_uid: $uid})-[:COSPEND_WITH*1..3]-(peer:Address)
RETURN DISTINCT peer.address_uid AS uid, peer.class AS class
LIMIT 500;
// Depth-capped at 3: co-spend closure is transitively explosive and an
// uncapped traversal will merge half of Bitcoin into one cluster.


// Q7 — SUBGRAPH EXTRACTION FOR GNN INFERENCE
MATCH (seed:Address {address_uid: $seed_uid})
CALL apoc.neighbors.athop(seed,
    'SENT_NATIVE|SENT_TOKEN|UTXO_FLOW|INTERNAL_CALL', $k_hops)
YIELD node
WITH collect(node) + seed AS nodes
UNWIND nodes AS n
MATCH (n)-[r]->(m) WHERE m IN nodes
RETURN n.address_uid AS src, type(r) AS rel, m.address_uid AS dst,
       r.value_normalised AS w, r.block_ts AS ts,
       n.class AS src_class, m.class AS dst_class;
// Feeds the PyG heterogeneous batch builder. Node/edge TYPE is returned
// explicitly because a homogeneous collapse loses exactly the relational
// semantics HGT exists to exploit.


// Q8 — REFRESH CACHED CLASSIFICATION AFTER INFERENCE
UNWIND $rows AS row
MATCH (a:Address {address_uid: row.uid})
SET a.class               = row.class,
    a.class_probability   = row.probability,
    a.is_absorption       = row.is_absorption,
    a.class_model_version = row.model_version,
    a.class_cached_at     = timestamp()
WITH a, row
CALL apoc.create.addLabels(a, row.extra_labels) YIELD node
RETURN count(node);

24.2  CACHE INVARIANTS
  CI-1  Redis is a cache and a broker. It is never a system of record.
        A total Redis flush must degrade performance and nothing else.
  CI-2  Any cached value that reaches a dossier carries its original
        fetched_at from PostgreSQL, not the cache write time.
  CI-3  Classification cache keys include the model version, so promoting a
        model naturally invalidates the cache without an explicit purge.
  CI-4  Distributed locks use SET NX PX with a random token and a Lua
        compare-and-delete release. A naive DEL release can delete another
        worker's lock after a timeout.
  CI-5  maxmemory-policy = allkeys-lru; eviction is expected and safe.

24.3  RATE LIMITING (token bucket, Lua-atomic)
  -- KEYS[1] = phm:rl:{provider}, ARGV = capacity, refill_rate, now, cost
  -- Returns 1 if allowed, 0 if throttled, plus retry-after seconds.
  Per-provider AND per-trace budgets are both enforced so one large trace
  cannot starve concurrent traces (PRD NFR-PERF-005).

26.  DATA LIFECYCLE, BACKUP & LEGAL HOLD
═════════════════════════════════════════════════════════════════════════════

  BACKUP
    PostgreSQL : continuous WAL archiving + nightly base backup.
                 RPO ≤ 15 min (PRD NFR-REL-005).
    Neo4j      : nightly dump. Lower priority — fully rebuildable from
                 PostgreSQL, which is why the derived-store rule in §1 exists.
    Object store: cross-region replication for phantasm-evidence only.
    Redis      : no backup required by design.

  RESTORE DRILL
    Quarterly, with a documented runbook, restoring to a scratch environment
    and verifying: audit chain intact, dossier hashes match, a sample trace
    reproduces byte-identically from its pinned parameters.

  LEGAL HOLD
    legal_hold on cases cascades logically to all child artefacts and to the
    object-lock retention on associated evidence objects. Releasing a hold is
    a privileged, audited, two-person action.

27.  MIGRATION STRATEGY
═════════════════════════════════════════════════════════════════════════════

  - Versioned, forward-only migrations (Alembic). Every migration has a
    documented rollback plan even where an automated down-migration is unsafe.
  - Ledger tables: additive changes only. A column may be added; a column
    that has ever held evidence is never dropped or retyped. Deprecated
    columns are commented as such and left in place.
  - Enum evolution: ADD VALUE only; never rename or remove a value that
    appears in a persisted row, because a dossier's meaning must not shift
    under it.
  - Zero-downtime pattern: expand → backfill → contract, with the contract
    step deferred to a later release than the expand step.
  - Neo4j schema changes are applied per shard with an idempotent script and
    verified by a post-migration constraint check.
  - Every migration that touches an evidence-bearing table requires a second
    reviewer, mirroring the two-person rule used for model promotion.
